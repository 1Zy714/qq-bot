# 跨会话摘要 + 成长附录

两个「原生没有」的能力，按 [dsh-qq-bot-playbook](https://github.com/rentaoyan0628-collab/dsh-qq-bot-playbook) 的
`playbook/06-custom-features.md` 设计，在**官方开放平台这条路**上重做了一遍。

| 能力 | 文件 | 解决什么 |
|---|---|---|
| 跨会话摘要 | `cross_session.py` | A 私聊问「B 刚才说什么」，以前一脸茫然；现在能答，且不越界 |
| 成长附录 | `growth_log.py` | 模型会忘记自己变过；现在有一本只准往后写、改历史会被发现的本子 |

两条路都不碰腾讯网关结构：跨会话摘要纯内存，成长附录只追加一个 JSONL。

---

## 一、跨会话摘要

### 它怎么工作

```
入站消息（群里/私聊，不管回不回）
      │  QQBotClient 里先 record_incoming()
      ▼
内存索引：每会话最近 14 条，保留 30 分钟，最多 200 个会话
      │
      │  有人问「刚才 / 最近 / 谁说了什么 / 某个昵称」时
      ▼
digest() 现算 → 拼进 **这一轮的 user 消息** → 模型回答
```

三个刻意的设计：

1. **读时现算，不预写摘要**。早期方案是每条消息后写一份摘要落盘，结果①用工具发的回合
   不触发写入、②摘要永远落后一轮。现算两件事一起解决，也不增加每轮开销。
2. **拼 user，不拼 system**。system 前缀要逐字稳定，llama.cpp 的前缀缓存才命中；
   user 消息每条本来就是新的，加多少都不亏。
3. **不落盘**。只回答「刚才」，重启丢就丢了——顺带避免了把群聊原文写进磁盘。

### 可见规则（比 playbook 更保守）

| 提问场景 | 能看到 |
|---|---|
| 群聊 | **只有本群**最近消息 |
| 私聊 | 群里最近几条（群本来就是多人可见）+ **被点名者**的私聊近况（带名字、带时间） |
| 任何场景 | 别人的私聊内容，**没有点名就永远看不到** |

与 playbook 的差异（有意为之）：它允许「群聊里也能看到群成员的私聊近况」，我这里**禁掉了**。
原因是官方 openid 给不了可靠的身份映射——群成员的 `member_openid` 和私聊的 `user_openid`
是两个不同的值，只能靠昵称模糊匹配。把私聊内容抛进群，风险远大于收益。

### 触发条件

不是每句都注入。命中以下任一才拼：

- 提问里出现**已知昵称**（≥2 个字、不是「大家」「你们」这类停用词）
- 提问里有问句线索：`刚才 / 刚刚 / 最近 / 上次 / 说了什么 / 聊了什么 / 他们 …`

日常闲聊走空串，不白烧 token。

## 二、成长附录

### 「只准追加」是机制，不是口头约定

| 层 | 做法 |
|---|---|
| 接口层 | `GrowthLog` 只有 `append` 和读，没有任何改 / 删函数 |
| 文件层 | JSONL 逐行 `open(..., "a")`，从不重写整个文件 |
| 链校验 | 每行 `hash = sha256(prev | ts | text)`；改任何一行，从它开始全断 |

**链断之后**：注入时显示 `⚠️链断`，并且**拒绝继续写**——否则断点会被越埋越深，
最后整本本子都不可信。

### 三重限流

| 限流 | 默认 | 说明 |
|---|---|---|
| 单条字数 | 200 | 成长是「一句反思」，不是日记 |
| 每天条数 | 10 | 不设上限，模型一天能写满一本 |
| 最小间隔 | 1800 秒 | 防止连发；同一条内容重复也会被拒 |

### 模型怎么写

回复里带标记即可，标记**在分片之前摘掉**，绝不会发进群里：

```
行，这次我记下了。[成长:被纠正后先问清再动手，别急着替人下结论]
```

一行可以有多条；`[成长:内容]` 和 `【成长：内容】` 都认。省略号/半截标记不会误触发。

### 谁能写

默认**只允许私聊触发**（`growth_allow_private: true`）。群聊默认全拒——
群里任何人只要能骗模型吐一句 `[成长:...]`，就能往这本只准往后写的本子塞东西。

想放开某个群：`growth_allow_groups: ["<群 openid>"]`（`"*"` = 全部群）。
想只认主人：`growth_owner_openids: ["<主人 openid>"]`，非空时其它人一律不算。

主人随时可以查看：群里/私聊发「**成长记录**」（或「成长附录」「成长列表」），
直接读文件回复，不经模型。

## 三、代码接入点

| 位置 | 改了什么 |
|---|---|
| `official_bot.py` `Responder.__init__` | 建 `self.cross` / `self.growth`（配置可关） |
| `system_context()` | 追加成长附录（只在新条目出现时变化，不打掉前缀缓存） |
| `answer()` | 跨会话摘要现算并拼进 user 消息；摘 `[成长:...]` 落盘；「成长记录」指令 |
| `_handle_group_message()` | 判定**之前** `record_incoming()`——被闸门挡掉的闲聊才是摘要的原料 |
| `on_group_at_message_create()` / `on_c2c_message_create()` | 同样先记录再回复 |

## 四、配置项

都在 `config.json`（不填就用默认值；`config.example.json` 有完整注释）：

```json
"cross_session_enabled": true,
"cross_session_max_chars": 700,
"growth_enabled": true,
"growth_path": "",
"growth_max_chars": 200,
"growth_per_day": 10,
"growth_min_interval_seconds": 1800,
"growth_allow_private": true,
"growth_allow_groups": [],
"growth_owner_openids": []
```

成长附录默认落在 `memory/growth.jsonl`（已被 `.gitignore` 挡住）。

## 五、怎么验证

### 离线（不连网关、不跑模型，各一秒内）

```bash
cd ~/qq-bot
python3 test_cross_session.py     # 隐私边界 / 触发条件 / 预算
python3 test_growth_log.py        # 标记 / 三重限流 / 哈希链 / 断链行为
```

### 成长附录文件

```bash
python3 growth_log.py --verify    # 链校验
python3 growth_log.py --tail 5    # 看最近 5 条
```

### 运行期日志

```bash
bash svc.sh restart official
bash svc.sh log official
```

| 日志 | 含义 |
|---|---|
| `[qq][growth] 记下一条：…` | 写入成功 |
| `[qq][growth] 未写入（too_soon）` | 被限流拦住（正常） |
| `[qq][growth] 未写入（chain_broken:lineN）` | 附录文件被改过，需要人工处理 |
| `[qq][growth] 来源不在允许名单` | 群里尝试写成长，被拒（正常） |
| `[qq] 成长指令 c2c:… -> …` | 「成长记录」查询被响应 |

## 六、已知边界（不掩饰）

1. **官方 openid 无法把「群成员」和「私聊用户」对齐**。只能按昵称匹配，同名会误认。
   所以私聊的近况只在**明确点名**时放开，且最多取最近 3 条。
2. **私聊里的「群聊内容」会跨群聚合**：拿不到「这个人在哪个群」，只能给最近几条。
   宁可少给，不给整段。
3. **重启就清空**（跨会话摘要）。这是有意的：只回答「刚才」，不做长期档案。
4. **模型未必会用标记**。它得先知道有这本本子——system 后缀里已经写了提示；
   如果它长期不写，可以调 `growth_min_interval_seconds` 或把提示写进人设。
5. **成长附录不是越写越好**。默认提示里明确要求「不写进度、不复述对话、没真变化就别写」，
   但模型天然爱写，限流是最后一道保险。

## 七、排障

| 症状 | 看一眼 |
|---|---|
| 问「刚才谁说了什么」还是不知道 | 那个群有没有收到全量消息？只 @ 的群消息不进索引 |
| 私聊里能看到别人的私聊 | ⚠️ 不该发生：检查是否点名命中，去 `test_cross_session.py` 复现 |
| 成长一直不写 | ①是不是群聊（默认拒）②是不是 30 分钟内写过 ③当天满 10 条了 |
| 成长写了但回复里还带着标记 | 标记被截断成半截了：看 `max_reply_chars` 是否太小 |
| 「成长记录」说链断 | 文件被手工改过；`python3 growth_log.py --verify` 定位行号，从断点前手工恢复 |
| 回复变慢 / 变长 | 摘要注入量：调小 `cross_session_max_chars` |
