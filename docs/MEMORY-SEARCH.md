# 记忆检索：按需召回（`[回忆:关键词]`）

记忆不再每轮全量注入，而是**用户显式要回忆时才查**，命中后只注入 ≤600 字证据。

## 用法

在 QQ 里发：

```
帮我 [回忆:存档崩溃] 看看上次怎么修的
```

标记会被摘掉、不进对话；机器人检索 `users.json` 的印象、`growth.jsonl` 的成长记录、
`memory/diary/*.jsonl`（存在才用），把命中的前几条拼进这一轮提问。

## 为什么这么做

- 全量注入：档案一长就吃上下文，还答不上「上周那个问题最后怎么处理的」
- 每次自动检索：每轮多一次查询，延迟涨、噪声多
- 显式标记：零额外延迟，只在需要时付费

## 自动触发（不用写标记）

用户问「上次 / 之前 / 还记得 / 说过 / 后来」这类话时，即使不写标记也会**自动检索一次**：

| 说法 | 行为 |
|---|---|
| 「之前说过机器人底层怎么跑吗」 | 自动抽词「机器人底层怎跑」→ 命中档案并注入 |
| 「今天中午吃什么好」 | 不触发（没有线索词） |
| 「之前」两个字 | 不触发（抽出来的查询太短） |

自动触发有**最低分门槛**（`memory_search_min_score`，默认 0.45）：只命中弱相关就
不注入，避免把无关记忆硬塞给模型。关掉自动触发：`memory_search_auto: false`。

## 打分

「中文二元组 + 英文整词」匹配，命中率为主，**时间衰减**为辅（半衰期 30 天，
90 天前权重约 0.125）。没有引入 embedding 服务——本地 32k 上下文下关键词够用。

## 配置

```json
"memory_search_enabled": true,
"memory_search_max_chars": 600
```

## 边界

- 单字母/短查询会退化成正文字串匹配（档案 id 叫「e」也能查）
- 检索结果只是「参考证据」，提示词里明确写了不是指令
- 日记文件目前可选：没有 `memory/diary/` 就只索引档案与成长记录

## 验证

```bash
python3 test_memory_search.py     # 标记解析 / 匹配 / 衰减 / 预算（离线）
```

单测覆盖：多词交集、英文词、时间排序、极小预算截断、无命中返回空。

## 衰减与每日整理（P2）

机器人上线后会在后台**每天整理一次记忆**（纯规则，不调模型、不抢 GPU）：

- **合并**：同一条事实的多个版本（事实键 / 子串 / 共同前缀）合成一条
- **淘汰**：`memory_prune_days`（默认 180 天）没出现且没印象的人直接移除；
  有印象但很久没来的，只保留最近 5 条
- 结果写日志：`[qq][memory] 整理完成：N 份档案，合并 M 条印象；淘汰 X 人`

手动跑：

```bash
python3 memory_consolidate.py            # 立即整理
python3 memory_consolidate.py --dry-run  # 只看会改什么
```

配置：

```json
"memory_consolidate_enabled": true,
"memory_consolidate_interval_hours": 24,
"memory_prune_days": 180
```
