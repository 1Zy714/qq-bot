## 二、三个坑（下次装插件必看）

### 坑 1：全局 `dsh` 比 host 旧

| 位置 | 版本 |
|---|---|
| `~/project/deepseek-harness` 的 `pnpm dsh` | **0.2.1-rc.3** ← 正在跑的 GUI 用它 |
| `~/.npm-global/bin/dsh` | 0.2.1-alpha.2 |

**装插件必须用 checkout 的 `pnpm dsh plugin --profile web ...`**，用全局 `dsh` 会装进版本语义不对的 profile。

### 坑 2：pnpm store 版本不匹配（最花时间）

```
ERR_PNPM_UNEXPECTED_STORE
deps linked from store/v10, pnpm now wants store/v11
```

- profile 是 pnpm 10 时代建的（`lockfileVersion: 9.0`）
- 当前 pnpm 是 **11.28.5**，corepack 缓存里还留着 **pnpm 10.32.1**
- 解决办法：用 pnpm 10 跑插件命令，不动全局版本

```bash
# 已固化成 ~/.local/bin/pnpm10
PATH=/tmp/pnpm10:$PATH node --import tsx/esm apps/cli/src/bin.ts plugin --profile web add <pkg>
# 或直接：cd ~/project/deepseek-harness && PATH=$HOME/.local/bin:$PATH pnpm10 ... ?
```

> 注意：`pnpm dsh` 会 spawn PATH 里的 `pnpm`，所以 shim 必须放在 PATH 前面。

### 坑 3：命令被中断会留下「半装」状态

第一次装 `dshmarket` 时连接被掐断：

- `pnpm` 进程成了孤儿，卡在写已关闭的管道上（无子进程、锁文件已写完、pnpm.log 0 字节）
- 结果：`package.json` 里有依赖、`node_modules` 里有包，但 **`dsh.profile.bundles` 没写进去** → 插件装了但不加载

判断与修法：

```bash
node -e "console.log(require('/home/lzy959/.dsh/profiles/web/package.json').dsh.profile.bundles)"
# 少了就手工补进 bundles，然后验证：
cd ~/project/deepseek-harness && pnpm dsh --profile web --dump-config | grep -i <插件名>
```

`--dump-config` 是**不重启就能验证**的好命令（会加载并组合所有 bundle patch）。

## 三、验证方式

npx -y @liustack/modlens doctor

**没有 `dev:web` 监听**，所以不会自动热更。

## 四、视觉引擎：三选一（未定）

modlens 的 doctor 结果：`antigravity-cli` 不在 PATH、`gemini-api` 缺 key、`openai` 缺 baseUrl、
`anthropic` 缺 key；本地链路里只有 `claude-cli`（装了但**没登录**）。

| 方案 | 成本 | 速度 | 隐私 |
|---|---|---|---|
| 本地 Ollama VL（需 pull，如 qwen3-vl:8b ≈ 6GB） | 显存换钱 | 10~30s | 全本地 |
| 免费 Gemini API key（aistudio，3 分钟，免卡） | 免费额度 | 5~10s | 图上传 Google |
| 登录 Claude Code 复用（`claude` 已装） | 走订阅 | 5~10s | 图上传 Anthropic |
| 任意 OpenAI 兼容网关（AIHubMix/GLM 等） | 按量 | 5~10s | 看网关 |

决定后用一条命令配置，例如本地：

```bash
npx @liustack/modlens config set openai.baseUrl http://127.0.0.1:11434/v1
npx @liustack/modlens config set openai.model qwen3-vl:8b
# apiKey 随便填非空（本地不校验）
```
