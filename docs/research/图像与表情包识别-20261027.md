# 图像识别 / 表情包识别 —— 方案调研（2026-10-27）

> 触发：主人要「搜一下图像识别、表情包识别的方案」。
> 结论：**表情包先做 OCR（零显存、当天能上），图片理解再上 2B 小 VLM（能挤进显存），
> CLIP 做粗筛、云端做兜底**。不要一上来就上大模型。

---

## 一、本机现状

| 项 | 现状 |
|---|---|
| 显存 | 16 GB，Strata 文本模型已占 **13.4 GB** |
| Ollama | 只有 `qwen3.8-27b-local`（文本），**没有视觉模型** |
| OCR | RapidOCR / PaddleOCR / tesseract **全没装** |
| DSH 侧 | `@liustack/modlens` 已装但**没配视觉引擎** |
| 机器人侧 | 表情包有标签系统，但打标只靠**文字猜测**（`infer_tags_from_text`：群友说「笑死」就把图打个「搞笑」），完全没有看图能力 |

机器人现在的表情包链路：收图 → 存库（无标签）→ 靠群聊文字猜标签 → 模型用 `[表情:标签]` 挑图。

## 二、需求拆成三件

1. **认图**：群友发的截图/照片/表情包，机器人要能看懂（现在只会说「[发了一张图]」）
2. **给表情包打标**：入库时自动打情绪/梗标签，挑图才准
3. **读懂文字梗**：中文表情包绝大多数是**带字的图**（「破防了」「笑死」），文字才是主要信息

第 3 点决定了优先级：**OCR 比 VLM 更重要、更便宜**。

## 三、候选方案

| 方案 | 显存 | 速度 | 中文梗图效果 | 成本 |
|---|---|---|---|---|
| **RapidOCR**（ONNX，CPU） | **0** | 0.3~1s/张 | ✅ 文字梗直接可读 | 免费，本地 |
| **Qwen3-VL 2B**（Ollama） | **~2.6GB** | 3~10s/张 | ✅ 能描述画面+情绪 | 免费，本地 |
| Qwen3-VL 4B/8B | 6~10GB | 5~15s | 更好，但**挤不进** | 免费，本地 |
| **Chinese-CLIP** 零样本 | ~1GB | 毫秒级批量 | ⚠️ 只给粗类（可爱/搞笑/无语） | 免费，本地 |
| **云端 VLM**（Gemini 免费 key / AIHubMix / GLM） | 0 | 5~10s | ✅ 最强 | 免费额度/按量，**图外传** |
| **modlens**（DSH 插件） | 取决于引擎 | 5~10s | 给我（agent）读图，不是给机器人 | 需要引擎 |
| vision-toolkit（DSH 插件） | 同上 | 同上 | 长截图 OCR、UI 还原 | 需要 provider |

### 关键数字（实测/官方）

- Ollama 的 `qwen3-vl` 有 **2b / 4b / 8b / 32b / 235b** 等标签；`2b` 系列下载体积 **1.9~2.7 GB**
- RapidOCR 最新 **1.4.4**（PyPI 镜像可用），ONNX 推理、纯 CPU
- Strata 13.4 GB + qwen3-vl:2b 2.6 GB ≈ **16.0 / 16.3 GB** —— 勉强能共存（要实测）
- 游戏开着再占 5 GB → **同时开游戏 + 文本模型 + 视觉模型不可能**

## 四、推荐路线

### P0：OCR 打标（零显存，半天）

```
收图（sticker_lib.collect）→ 后台异步 RapidOCR → 文字 → 规则/同义词表 → 标签
```

- 中文梗图（占大多数）立刻有标签，挑图准确度直接提升
- 识别失败/超时一律降级为「无标签」，不影响收图
- 缓存：按图片 sha1 存 OCR 结果，同一张图只跑一次
- 依赖：`rapidocr-onnxruntime==1.4.4`（~几十 MB，CPU）

### P1：小 VLM 描述（2.6GB，1 天）

- `ollama pull qwen3-vl:2b`，按需调用（不常驻）
- 用途：**没有文字的图**生成一句描述 + 2~3 个情绪词
- 与文本模型共享 16GB：需要互斥（用完卸载 VLM）或接受挤占；建议**只在入库时跑**，不要聊天时跑
- 实测点：Strata 与 2b 能否同时常驻

### P2：CLIP 粗筛（可选）

- Chinese-CLIP 零样本，给「可爱 / 搞笑 / 无语 / 生气」这类粗标签，毫秒级、可批量
- 适合图库大了以后做筛选，不适合精细标签

### P3：云端兜底（可选）

- 只在 OCR 和本地 VLM 都判不出时，走 Gemini 免费额度（5~10s，需 key）
- 隐私：图会离开本机，群里别人的照片不要默认上传

### 顺带：给「我」也配眼睛

`modlens` 已经装在 web profile，只要配一个引擎（本地 Ollama 的 qwen3-vl，或免费 Gemini key），
我就能直接读主人发的截图/设计稿。和机器人侧是两条线，可以分开做。

## 五、显存/并发规划

| 场景 | 组合 | 可行 |
|---|---|---|
| 空闲 | Strata 13.4 + 视觉 2.6 | ⚠️ 勉强，实测 |
| 聊天中 | 只跑 Strata | ✅ |
| 打标（后台） | 卸 Strata，跑视觉，完事再装回 | ✅ 但切换慢（30s 级） |
| 游戏 + 聊天 | 游戏 5.1 + Strata 13.4 | ❌ 已经超了（这两天实测） |
| 游戏 + 视觉 | 5.1 + 2.6 | ✅ 但如果同时要聊天就没了 |

结论：**视觉任务必须异步、批处理**，别放在聊天路径上。

## 六、风险

1. **OCR 误读**：表情包字体花、描边字 OCR 容易错；标签错只影响挑图，不会让消息出错
2. **梗的语气标签污染**：OCR 出来的字直接当标签可能过度拟合（如「哈哈哈」→「搞笑」合理，但「我死了」可能只是陈述）——用同义词表 + 置信度门槛
3. **显存挤压**：2B 视觉模型与文本模型共存会掉速，需要实测再决定常驻还是按需
4. **隐私**：云端方案会让图片离开本机；机器人收的图很多是群友自拍，默认应走本地

## 七、建议的落地顺序

| 步骤 | 工作量 | 收益 |
|---|---|---|
| 1. RapidOCR 装进 qqbot venv，写 `sticker_ocr.py`（异步、缓存、降级） | 半天 | 文字梗图全部可检索/可挑 |
| 2. 接进 `sticker_lib.collect`，入库时打标；失败不影响收图 | 半天 | 表情包库第一次「看得懂」 |
| 3. `ollama pull qwen3-vl:2b`，给无字图做 caption | 1 天 | 覆盖剩下 20~30% |
| 4. 给 modlens 配本地/云端引擎 | 半小时 | agent 也能读图 |

## 八、DSH 生态里的现成插件（2026-10-27 查）

结论：**有，但没有「纯分类器」**——全是「视觉模型 + 缓存/知识库」的组合。

| 插件 | ★ | 做什么 | 依赖 |
|---|---|---|---|
| [yyh-001/dsh-meme](https://github.com/yyh-001/dsh-meme) | **400** | 表情包：一键发图、斗图、情绪主动发图、**AI 自动识图入库**、GIF 抽帧拼胶片条；适配 dsh-im 与 **QQ 官方机器人**（`send_meme` 带 absPath → `qqbot_send_file`） | **需要支持图片输入的模型** |
| [Loping151/dsh-nekowhale-stickers](https://github.com/Loping151/dsh-nekowhale-stickers) | 73 | 表情包**知识库**：逐张标注场景/动作/关联梗/方向；MCP server + `[sticker:名字]` 标记；**对模型视觉依赖低**，常驻约 60 token | 预标注数据，不需要视觉模型 |
| [710765989/dsh-sticker-dict](https://github.com/710765989/dsh-sticker-dict) | 0 | **识别缓存**：按 sha256 记住「看过的图」，避免重复识图；GIF 均匀抽帧拼联系表；支持人工批注 | 配合任意视觉模型 |
| [zaofan-make/dsh-qqbot](https://github.com/zaofan-make/dsh-qqbot) | 146 | QQ 群管 + **表情包自动入库** + AI 决定开口 | DSH 侧 |
| [tencent-connect/dsh-qqbot](https://github.com/tencent-connect/dsh-qqbot) | **295** | **官方** QQ Bot 接入 DSH 的插件（和主人现在的自写 botpy 是两条路） | DSH 渠道 |
| [xmanrui/dsh-im](https://github.com/xmanrui/dsh-im) | 2672 | 通用 IM 渠道（QQ/微信/飞书/钉钉…）接入 DSH | DSH 渠道 |

**对主人的启发**：

1. `dsh-nekowhale-stickers` 的标注体系（场景 / 动作 / 梗 / 方向）可以直接拿来当
   本地 `sticker_lib` 的标签规范——它不依赖视觉模型，靠预标注，常驻开销极小。
2. `dsh-meme` 的「GIF 抽帧拼胶片条再识图」和「sha256 记住看过的图」两个思路，
   正好补上我们 OCR 方案缺的两块（动图、重复识别）。
3. 更大的发现：**官方有 `tencent-connect/dsh-qqbot`**（★295）——如果哪天想让机器人
   彻底跑在 DSH 渠道上，这是官方路线，和现在的自写 `official_bot.py` 可以并存评估。
