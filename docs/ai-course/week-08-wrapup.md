# Week 8 · 收尾：写清楚 + 讲明白

> 目标：把第 7 周的工作变成「可展示的资产」：一篇文档、一段简历、一次 3 分钟讲解。

---

## Day 1–2 · 写技术文档

`docs/<你的功能>.md`，固定结构：

```markdown
# <功能名>

## 背景
为什么要做（一句话：原来缺什么）

## 方案
- 工具：<MCP 工具名>，负责什么
- 数据：从哪来、怎么存
- 提示词：模型在什么条件下调用

## 实现要点
- 关键代码位置：<文件:行>
- 降级策略：<失败时怎么办>

## 验证
- 命令：<怎么复现>
- 结果：<日志/截图/单测输出>

## 坑
| 现象 | 原因 | 处理 |
```

**标准**：一个没参与的人照着能复现。

---

## Day 3 · 简历素材（3 条 STAR）

模板：

| 要素 | 写法 |
|---|---|
| S（背景） | 原有 QQ 机器人只能聊天，不能<能力> |
| T（任务） | 独立完成<能力>的接入与验证 |
| A（行动） | 封装 MCP 工具、加降级、补 2 个单测、写文档 |
| R（结果） | 现在可以<一句可验证的效果>；失败场景不崩 |

写进简历「AI 应用实践」小节，控制在 2~3 行。

---

## Day 4 · 3 分钟讲解脚本

```
0:00–0:30  背景：项目是什么、要解决什么
0:30–1:30  方案：工具怎么封、提示词怎么设计、数据怎么存
1:30–2:30  难点：外部依赖失败怎么办、怎么验证动作真的生效
2:30–3:00  结果与反思：数据/后续优化
```

对着镜子或录音练两遍，卡壳的地方回去补文档。
